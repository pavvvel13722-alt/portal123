# Офлайн-портал обработки обращений

## Обзор
Портал предназначен для локальной работы с выгрузками обращений из ВТБ-сферы в формате CSV. Все вычисления выполняются в браузере без сети и серверов: определение дублей, полнотекстовый поиск и автоматический сбор тегов. Интерфейс открывается напрямую из файла `index.html`, а необходимые библиотеки размещены в каталоге `js/vendor`. Пользовательские настройки сохраняются в `localStorage`, поэтому конфигурация остается между сессиями браузера.

### Поддерживаемые CSV-выгрузки
- Разделитель: точка с запятой `;`, поля могут быть заключены в кавычки.
- Кодировки: UTF-8 (включая UTF-8-BOM) и Windows-1251.
- Объем: рассчитано на файлы свыше 10 000 строк.

Во время импорта портал определяет разделитель, удаляет BOM, нормализует заголовки и формирует единый объект обращения. При отсутствии колонки значения берутся из смежных полей: например, автор восстанавливается из заявителя или контакта. Этот же механизм используется всеми вкладками и скриптом `tests/smoke.js`.

## Структура приложения
Пользовательский интерфейс разделен на три вкладки:

1. **Дубли обращений** — группирует похожие обращения одного автора.
2. **Поиск по обращениям** — выполняет поиск и фильтрацию с учетом категорий.
3. **Поиск тегов** — собирает характерные n-граммы для каждого шаблона обращения.

Каждая вкладка реализована отдельным модулем (`app.dups.js`, `app.search.js`, `app.tags.js`) и при необходимости передает тяжелые вычисления в Web Worker (`app.dups.engine.js`, `app.tags.engine.js`). Если запуск воркера невозможен, используется синхронный резервный режим. Стили расположены в `css/style.css`, там же описано переключение светлой и темной темы (значение хранится в `localStorage.theme`).

## Вкладка «Дубли обращений»
Определяет группы обращений, отправленных одним и тем же автором, и оценивает схожесть описаний.

### Подготовка текста
- ФИО автора приводится к нижнему регистру, буква «ё» заменяется на «е», лишние пробелы удаляются.
- В расчет включается только поле «Описание»: текст переводится в нижний регистр, очищается от пунктуации и HTML, разбивается на буквенно-цифровые токены.
- Настраиваемые стоп-фразы исключаются. Список хранится в `localStorage.dupStopPhrases` и редактируется во вкладке.
- Выполняется легкий стемминг с применением словаря синонимов (например, «vrm» и «врм» считаются одним термином).

### Модель похожести
Для каждого автора рассматриваются пары обращений внутри заданного окна по дате. Вычисляются две метрики:
- **T3** — косинусное сходство символьных триграмм.
- **J3** — индекс Жаккара для 3-словных шинглов.

Итоговый скор `S = 0.60 * T3 + 0.40 * J3`. Порог зависит от длины описания:
- меньше 8 токенов — требуется `S ≥ 0.80`;
- от 8 до 19 токенов — `S ≥ 0.70`;
- 20 токенов и более — `S ≥ 0.62`.

Порог можно зафиксировать вручную, отключив «умный» режим. Подходящие пары объединяются в кластеры с помощью структуры «union-find». Главным обращением становится запись с самой поздней датой создания; остальные помечаются как дубли.

### Работа оператора
- Шапка каждого кластера показывает автора, ссылку на основное обращение и общее количество дублей для закрытия.
- Кнопка «Не дубль» удаляет всю связку из текущего списка, чтобы она не попадала в экспорт.
- Для каждой записи указаны ID, дата создания, процент похожести, доля общих токенов и сниппет с подсветкой совпадений.
- Доступны быстрые действия:
  - «Открыть в сфере» формирует ссылку `https://sfera.vtb.ru/sd/support?open=` + `encodeURIComponent(ID)`.
  - «Скопировать комментарий» — шаблон закрытия: «Ошибочное обращение / Дубль обращения <MASTER_ID>. Работы продолжаются там.»
- Кнопка экспорта сохраняет `duplicates.csv` (UTF-8 BOM, разделитель `;`, все поля в кавычках).

### Настройки
- **Окно по дате** — сравнивать обращения в пределах выбранного числа дней (по умолчанию 14, можно отключить).
- **Минимальный порог** — единый порог для всех описаний при выключенном умном режиме.
- **Стоп-фразы** — редактируемый список фраз, исключаемых перед анализом.
Все параметры сохраняются в `localStorage.dupSettingsV2`.

## Вкладка «Поиск по обращениям»
Позволяет находить обращения по ключевым словам и фильтрам.

### Индексация и поиск
- Индексируются поля ID, Автор, Описание, Сервис и Теги. Полнотекстовый поиск использует только автора и описание.
- Весовые коэффициенты: точная фраза (2–3 слова) +5, точное слово +2, похожее слово (расстояние Левенштейна ≤ 1) +1. Совпадения в сервисе или тегах умножаются на 1.2.
- Результаты упорядочены по суммарному весу. Таблица отображает колонки: ID, Описание, Создано, Статус, Приоритет. Автор скрыт на экране, но попадает в экспорт.

### Фильтры и действия
- **Статус** и **Приоритет** — мультиселекты с уникальными значениями из набора данных.
- **Поисковая строка** — подсвечивает найденные слова в описании; добавляет «чипы» с ключевыми словами.
- **Сбросить фильтры** — очищает поиск и выбранные значения.
- Над таблицей отображается счетчик вида «Найдено: N».
- **Экспорт результатов (CSV)** — выгружает текущую таблицу в формате `ID;Автор;Описание;Создано;Статус;Приоритет` (UTF-8 BOM, поля в кавычках).

### Категории
Категории — это сохраненные наборы ключевых слов.
- Список категорий располагается слева. Клик запускает поиск по ключам категории.
- Кнопка «Редактировать» открывает модальное окно с именем, списком ключей (по одной строке или через `;`) и порогом веса.
- Кнопка удаления удаляет категорию немедленно.
- Доступны импорт и экспорт набора категорий в JSON.
- Данные сохраняются в `localStorage.searchCategoriesV2`.

## Вкладка «Поиск тегов»
Агрегирует повторяющиеся фразы в описаниях для каждого шаблона (значения поля «Название»).

### Фильтры и параметры
- **Шаблон** — мультиселект по уникальным названиям обращений.
- **Статус** — мультиселект, по умолчанию выбраны «Решено» и «Выполнено».
- **Параметры извлечения** — минимальная частота (3), размер n-грамм (1–3), минимальная длина токена (2), топ-N (25).
- Кнопки «Найти теги», «Сброс», «Экспорт CSV», «Экспорт JSON», «Копировать теги».

### Алгоритм
1. Отбираются строки с выбранным шаблоном и статусами.
2. Описания нормализуются (нижний регистр, замена «ё», удаление пунктуации, сжатие пробелов).
3. Исключаются служебные фразы и стоп-слова.
4. Текст токенизируется по буквенно-цифровому шаблону, применяется стемминг и словарь синонимов.
5. Формируются n-граммы (1–3 слова), вычисляются показатели:
   - TF — суммарная частота фразы.
   - DF — количество обращений, где фраза встречалась.
   - TFIDF = `DF * log(1 + M / (1 + DF))`, где `M` — число обращений шаблона.
   - LENBOOST — множитель 1.0 / 1.25 / 1.45 для униграмм, биграмм и триграмм соответственно.
   - DOMBOOST — дополнительный множитель 1.15, если фраза содержит доменные термины (vpn, vrm, rdp, nla, сертификат, crypto pro и др.).
6. Итоговый `SCORE = TFIDF * LENBOOST * DOMBOOST`.
7. Удаляются фразы, более 70% вхождений которых приходится на более длинные выражения.
8. Список сортируется по убыванию score, берутся топ-N записей и объединяются с пользовательскими правками.

### Управление результатами
- Заголовок блока отображает шаблон и количество обращений в выборке.
- Теги представлены «чипами» с частотой и score. Теги можно удалять или добавлять вручную; изменения сохраняются в `localStorage.tags_by_template_v1`.
- Таблица детализирует фразы (частота, DF, TF-IDF, score) с сортировкой по столбцам.
- Экспорт CSV формирует строки `Шаблон;Тег;Score;Частота` (UTF-8 BOM). Экспорт JSON создает объект вида `{ "Шаблон": ["тег1", "тег2", ...] }`.

## Настройки и хранение данных
| Назначение | Ключ в localStorage |
|------------|---------------------|
| Тема оформления | `theme` |
| Настройки дублей (порог, окно, флаги) | `dupSettingsV2` |
| Стоп-фразы дублей | `dupStopPhrases` |
| Категории поиска | `searchCategoriesV2` |
| Стоп-слова тегов и параметры | `tagSettingsV1` |
| Пользовательские теги по шаблонам | `tags_by_template_v1` |

Кнопка сброса настроек очищает все перечисленные ключи.

## Запуск тестов
В репозитории есть скрипт `tests/smoke.js`, который импортирует общий парсер, загружает файл `tickets_sample_100_same_author.csv` и проверяет наличие кластеров дублей и сгенерированных тегов. Запуск:

```
node tests/smoke.js
```

## Развертывание
1. Сохраните структуру каталогов (`css`, `js`, `js/vendor`, `tests`).
2. Передайте папку пользователям или разместите на общедоступном ресурсе.
3. Откройте `index.html` двойным кликом или через меню браузера «Файл > Открыть».
4. Загрузите CSV и продолжайте работу полностью офлайн.
